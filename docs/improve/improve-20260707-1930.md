### C-1 + C-4 — PivotConfigDialogs state ownership

**Current architecture**: `usePivotConfigDialogs()` hook in `pivot-config.tsx:25-67` owns 3 useState (`showCalcDialog`/`editingCalc`/`formatIndicatorKey`). Returns 9 fields. Panel destructures + passes 11 fields to `<PivotConfigDialogs>`. Sections receive setters (`setFormatIndicatorKey` l:191, `setEditingCalc`+`setShowCalcDialog` l:201-202) as triggers.

**Trigger tension**: Dialog open-state shared between Sections (triggers) + Dialogs (renderer). If Dialogs self-manages, how do Sections trigger opens?

**ora-1 verdict (Q1-Q3)**: SKIP. Current architecture is **standard React pattern** — hook owns state in lowest common ancestor, passes to both triggers + renderer. 11 props verbose but clear. "3-hop" claim misleading — hook is in Panel's render scope = 1 hop. `useReducer` for 3 independent useState adds boilerplate without benefit. `PivotConfigDialogs` as pure pass-through is **ideal** — presentation wrapper, no logic, no state.

**Options assessed**:
- (a) self-sub store data in Dialogs → -2 props, marginal, makes Dialogs harder to test
- (b) move hook to Dialogs file + export → hook returns setter wrappers, same as direct setters
- (c) render-prop → unnecessary indirection for 2 trigger points
- (d) skip → CORRECT

### C-40 — useAgentChat slim

**Current architecture**: `useAgentChat` (80L) computes `chatKey`, calls 3 leaf hooks, wires 2 cross-hook callbacks (`clearConversation` = history.clear + ai.clear; `sendMessage` = ai.clear + stream.send), manages `input` state, wraps `generateProfile`. Returns 15 fields. 1 consumer (`agent-chat.tsx`).

**ora-1 verdict (Q4-Q5)**: SKIP. `useAgentChat` is **legitimate composition hook** with real coordination value:
1. `chatKey` computation (shared by 3 leaf hooks)
2. `clearConversation` cross-hook atomic coordination
3. `sendMessage` cross-hook atomic coordination
4. `generateProfile` convenience wrapper (template string + stream.send)
5. `input` state management

Removing it → `agent-chat.tsx` duplicates ~20L coordination logic (53→75L). No benefit. 15-field flat return is reasonable — sole consumer uses all fields. Not forwarding, is orchestration.
