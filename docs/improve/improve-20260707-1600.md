## 1. Candidates

C-5 from Loop 1 explorer report: `sql-console.tsx:96-99` global `<style>` injection.

## 2. Grill

### Problem
2 CodeMirror consumers injected identical inline `<style>` blocks declaring global CSS rules:
```css
.cm-editor { height: 100% !important; }
.cm-scroller { overflow: auto !important; }
```

**Issues**:
1. **Global leakage** — `.cm-editor`/`.cm-scroller` are CodeMirror's own class names; rules apply to EVERY CodeMirror instance app-wide, not scoped to the consuming component.
2. **Duplication** — 2 consumers (`sql-console.tsx:96-99`, `create-widget-sql-dialog.tsx:132-135`) injected the same block, so 2 `<style>` tags pollute `<head>`/DOM.
3. **`!important`** — overrides any legitimate scoped styling, blocks future theming.

### Existing partial mitigation
Both consumers already had `[&_.cm-editor]:h-full` in CodeMirror's `className` prop (Tailwind arbitrary variant), which scoped the height rule per-instance. Only `.cm-scroller { overflow: auto !important }` lacked a scoped equivalent.

### Solution
- Delete both `<style>` blocks.
- Add `[&_.cm-scroller]:overflow-auto` to CodeMirror `className` in both consumers (scoped variant matching existing `[&_.cm-editor]:h-full` pattern).

### Why not extract a shared component?
`SqlConsole` (full editor + toolbar) and the dialog's editor (minimal editor + dialog run button) differ enough in structure that a shared wrapper would add abstraction cost for 2 call sites. The 4-line `className` addition is the minimal diff. Future loop if a 3rd consumer appears.
