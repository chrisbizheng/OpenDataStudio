## 2. Grill

### Architectural blocker (CRITICAL)

`useQueryOrchestrator()` runs SIDE EFFECTS (3 `useEffect`s at l:56-68: schema sync, default table execute, pivot reset). If `GridView` calls `useQueryOrchestrator()` itself → DUPLICATE EFFECTS (double execute, double pivot reset). Cannot naively self-subscribe.

**Split required**: separate controller (effects, called once) from selectors (called by many).

### Sub-candidates within Cluster B

- **B1: GridView self-subscribes** (highest depth, eliminates 16 props + page pass-through). Requires orchestrator split first.
- **B2: AssistantMessage follow-up hook + store subscription** (medium depth, eliminates 4-6 props). Independent of B1.
- **B3: `_t`/`lang` deletion** (low depth, Cluster C — deferred separately, do NOT fold in).
- **B4: page.tsx dead sqlText + half-dead handleAgentSqlGenerated** (hygiene, E-remainder fold-in).
- **B5: orchestrator return memoization** (`data` + `filteredRows` via `useMemo`) — perf foundation, required for safe self-subscription.

### Proposed split (pending oracle review)

- `useQueryController()` — runs effects (schema sync, default execute, pivot reset). Called ONCE in page.tsx. Returns nothing (or controller refs).
- `useQueryState()` — `useSyncExternalStore` on `queryLifecycle.state` + memoized `data` derivation. Consumers narrow with `useShallow`.
- `useQueryActions()` — stable action callbacks (`handleSort`, `handleSqlExecute`, `handleDrilldown`, `setSearchQuery`, `setPendingAutoExecute`, `loadMore`, `cancel`). Memoized.
- `useSchema()` — schema derivation (catalog + selectedTable/Database). Extracted from orchestrator.

### Open questions (for oracle + explorer)

1. **Split strategy**: separate hooks (`useQueryController`/`useQueryState`/`useQueryActions`) vs React Context provider (`QueryOrchestratorProvider` + `useQueryOrchestratorContext`). Context is more idiomatic but value changes every render (unless memoized). Separate hooks + `useSyncExternalStore` is more granular (no cascading re-renders). Which is better for this codebase?
2. **`data` derivation stability**: `data: state.data ? { ...state.data, rows: filteredRows } : null` creates new object every render. `useMemo` with what deps? `state.data` + `filteredRows`. If no (side effects), bigger problem.
3. **Agent-chat store shape** (for B2/P5): where do `aiFollowUpQuestions` + `isGeneratingFollowUpQuestions` live? `useAgentChatsStore`? Need explorer to map.
4. **`handleSqlGenerated` dead in GridView**: confirm truly dead (not passed to any child). If dead, P6 removes it + `onSqlGenerated` prop.
5. **`pendingAutoExecute` path**: who calls `setPendingAutoExecute`? If AgentChat, it's a cross-component deferred-execute. With GridView self-subscribing, this effect moves where?
