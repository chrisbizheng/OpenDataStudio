## 1. Candidates (from exp-1 scan, m0512)

### C-8 (HIGH, STRUCTURAL) — pivot-config cross-store write
`pivot-config.ts:135-149` `addCalculatedIndicator` still calls `usePivotExecutionStore.getState().setError(...)` at l:142, l:148. Loop D split config/execution but left this backdoor. Action mutates 2 stores. **REFACTOR**: return validation result `{ ok, errors }`, let caller (`use-pivot-orchestrator.ts` or `pivot-config-sections.tsx` CalculatedSection) push error to execution store.

### C-7 (HIGH, STRUCTURAL) — useAgentChatSessionStore flat not per-chatKey
`agent-chat-session.ts:6-47` — `isLoading`/`aiInitialQuestions`/`aiFollowUpQuestions`/`isGenerating*` are global. `useMessageHistory` chatKey effect calls `resetSession()` (l:53) on chatKey change BUT timing is racy. **Latent bug**: switch table mid-stream → `abortRef` doesn't fire (still in old hook closure), `isLoading` stays true, previous table's `aiFollowUpQuestions` visible. **FIX**: namespace by chatKey `Record<chatKey, T>` (same shape as `useAgentChatsStore.conversations[chatKey]`).

### C-24 (HIGH, MECHANICAL) — useQueryActions missing setSql
`use-query-orchestrator.ts:179-189` `useQueryActions` returns 9 actions but NOT `setSql`. `dashboard-canvas.tsx:81` bypasses hook: `useData().queryLifecycle.setSql(...)`. Loop B split exposed `setPendingAutoExecute` but missed `setSql`. **FIX**: add `setSql: (sql: string) => queryLifecycle.setSql(sql)` to `useQueryActions` return, replace direct call at `dashboard-canvas.tsx:81`.

### C-9 (HIGH, MECHANICAL) — useAgentChatsStore persist O(N) per write
`useMessageHistory:63` calls `setStoredConversation(chatKey, messages)` on every message change → `set({ conversations: { ...s.conversations, [key]: messages } })` → persist middleware re-serializes ALL conversations to localStorage. O(N) per write where N = total chat count. With streaming tokens = multi-MB writes per token. **FIX**: debounced persist (200ms) or `subscribe` middleware or `partialize` per-chatKey.
