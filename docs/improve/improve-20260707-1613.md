## 1. Candidates

Original C-2 from Loop 1 explorer: "`dashboard-selector-dialog.tsx` widget-creation side effect".

**Re-grill after reading both files**: explorer pointed at WRONG file. `dashboard-selector-dialog.tsx::addToDashboard` (99L) is the GOOD example — has try/catch + `adding` loading state + toast + button disable. `create-widget-sql-dialog.tsx::handleAddWidget` (383L, lines 97-112) is the BAD one — 3 bugs:

1. **Unhandled rejection**: `await createWidget(...)` at L100 has no try/catch. If `createWidget` throws (e.g., IndexedDB quota, store error), rejection propagates unhandled → React 19 logs warning, no user feedback.
2. **No loading state**: button `disabled={!queryResult}` (L376) only checks form validity, not async-in-flight. User can click again during `createWidget` await → duplicate `createWidget` call → duplicate widget added to dashboard. Real data-integrity bug.
3. **No toast feedback**: silent success (dialog closes) + silent failure (dialog stays open with no message). User has no confirmation.

## 2. Grill

- **Q1**: Hook extraction worth it? → NO. The 2 dialogs have different UX intents (sql-dialog silent close on success, agent-chat toasts). Forcing into 1 `useWidgetCreation` hook creates options/branches. Better: copy GOOD pattern (try/catch + loading + toast) to BAD dialog.
- **Q2**: Is "no toast" really a bug? → YES. User clicks "添加到仪表盘", nothing visible until dialog closes. If `createWidget` throws, dialog stays open with zero feedback. UX bug.
- **Q3**: Loading state? → YES. Button stays enabled during async → double-click → duplicate widget. Real data-integrity bug.
- **Q4**: State reset on error? → Current code resets `setSqlText("")` + `setQueryResult(null)` + `setError(null)` AFTER `await createWidget`. If throws, they don't run (preserve user input on error — correct). With try/catch, keep resets inside `try` after `await` to preserve this property.
- **Q5**: Other dialog patterns? → Agent-chat disables button via `disabled={adding === d.id}`. SQL dialog only `disabled={!queryResult}`. Add `|| adding` to disable during async.
- **Q6**: i18n keys? → Existing: `dashboard.added_to` (zh: "已添加到仪表盘"), `dashboard.add_failed` (zh: "添加失败"), `dashboard.add_to_dashboard` (button label). All reusable.

## 3. Plan

Single phase, direct edit (no specialist — <20 lines, 1 file, mechanical):

- Add `import { toast } from "sonner"`
