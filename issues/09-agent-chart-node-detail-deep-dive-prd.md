# Issue 9: Agent 图表节点详情增强 + AI 深度分析方向选择 PRD

**Type:** PRD
**Labels:** ready-for-agent
**Blocked by:** #7

---

## Problem Statement

用户在 Agent 聊天中点击图表节点后，会看到一个节点详情卡片。当前卡片只显示 `{节点值} → {度量值}`，例如 `北京 → 12,345`。当图表节点来自多个维度组合时，用户无法判断 `北京` 或 `北京 · 线上` 分别对应哪些字段，也无法判断右侧数值属于哪个度量。

同时，当前 `AI 深度分析` 按钮会立即发送固定分析请求，用户无法选择自己想要的分析方向。对于 BI 探索场景，用户可能想下钻、对比、看趋势、查明细、看占比或找异常。固定 prompt 会让 AI 分析结果偏离用户当前意图。

## Solution

增强 Agent 图表节点详情卡片：

1. 点击图表节点后，表头改为两行结构。
   - 第一行显示完整维度上下文：`字段名 = 字段值 · 字段名 = 字段值`
   - 第二行显示被点击的度量上下文：`度量字段名 = 度量值`
2. 表头字段名直接使用原始字段名，不使用 schema comment。
3. 下方节点明细表格保持现状，不改列、不改行数、不改截断、不改过滤逻辑。
4. `AI 深度分析` 按钮不再立即发送固定 prompt，而是在卡片内 inline 展开最多 4 个分析方向。
5. 分析方向默认由前端基于点击值、度量、图表类型、schema 字段类型本地推断；用户也可以点击 `AI 推荐方向` 调用 LLM 实时生成更贴合上下文的方向文案。
6. 用户点击某个方向后，系统发送带结构化上下文的自然语言 prompt，明确包含维度锁定条件、分析类型、分组字段和度量字段。

## User Stories

1. 作为数据分析用户，我想在点击图表节点后看到维度字段名和值 so that 我知道当前节点代表哪个数据切片。
2. 作为数据分析用户，我想在点击多维组合节点后看到每个维度的字段名 so that 我不用猜 `北京 · 线上` 中每一段的含义。
3. 作为数据分析用户，我想看到被点击度量的字段名 so that 我知道 `12,345` 是销售额、订单数还是利润。
4. 作为数据分析用户，我想在多 series 图表中看到我点击的是哪一条 series so that 我能确认当前分析焦点。
5. 作为数据分析用户，我想节点详情表头能自动换行 so that 多维度场景下信息不会被截断丢失。
6. 作为数据分析用户，我想下方明细表格继续保持原样 so that 已有使用习惯不被破坏。
7. 作为数据分析用户，我想点击 `AI 深度分析` 后先看到可选分析方向 so that 我可以决定 AI 下一步该怎么分析。
8. 作为数据分析用户，我想系统优先推荐下钻方向 so that 我可以继续拆解当前节点背后的组成。
9. 作为数据分析用户，我想系统推荐同维对比方向 so that 我可以比较当前节点和其他同类节点的差异。
10. 作为数据分析用户，我想系统推荐时间趋势方向 so that 我可以观察当前节点随时间的变化。
11. 作为数据分析用户，我想始终有明细查询方向 so that 我可以查看当前节点背后的原始数据。
12. 作为数据分析用户，我想在适合的图表中看到占比分析方向 so that 我可以理解当前节点对整体的贡献。
13. 作为数据分析用户，我想在存在多个数值字段时看到关联分析方向 so that 我可以探索指标之间的关系。
14. 作为数据分析用户，我想在数值度量场景中看到异常检测方向 so that 我可以快速发现偏离常态的数据。
15. 作为数据分析用户，我想在时序图中看到环比或同比方向 so that 我可以理解变化速度和周期性。
16. 作为中文用户，我想方向文案和 prompt 使用中文 so that 我能自然理解系统建议。
17. 作为英文用户，我想方向文案和 prompt 使用英文 so that 英文界面保持一致。
18. 作为 AI 分析用户，我想发送给 AI 的 prompt 明确包含字段名和值 so that AI 能生成准确的 WHERE 条件。
19. 作为 AI 分析用户，我想发送给 AI 的 prompt 明确包含度量字段 so that AI 不会分析错误指标。
20. 作为 AI 分析用户，我想发送给 AI 的 prompt 明确包含分组字段 so that 下钻分析能按正确维度聚合。
21. 作为产品用户，我想默认方向本地生成 so that 点击按钮后没有额外等待和 token 成本。
22. 作为数据分析用户，我想可以请求 AI 实时推荐方向 so that 方向文案更贴合当前数据上下文。
23. 作为开发者，我想分析方向推荐逻辑封装成纯函数 so that 规则可以被单独测试和维护。
24. 作为开发者，我想图表点击事件携带 seriesName so that Agent 聊天可以判断用户点击的是哪个具体 series。
25. 作为开发者，我想保持现有图表、表格和 Agent 消息结构兼容 so that 这个改动不会破坏已有聊天记录渲染。

## Implementation Decisions

- 扩展图表点击事件的数据契约，除当前的节点 key、数值 value、行数据 row 外，额外传递被点击的 seriesName。
- Agent 聊天中的节点详情状态同步扩展 seriesName 字段。
- 节点详情表头改为两行结构。
  - 第一行是维度上下文，格式为 `字段名 = 字段值`，多项用 `·` 分隔，并允许自动换行。
  - 第二行是度量上下文，优先使用被点击的 seriesName 表示点击焦点，否则回退到 visualization 配置中的 yKey。
- 维度字段从点击事件携带的 row 对象中提取。
- 度量字段集合来自 visualization 配置中的 yKey 和 series yKey；维度字段为 row 中排除度量字段后的字段。
- 字段展示名称直接使用原始字段名，不使用 schema comment，不增加字段别名映射。
- 节点明细表格维持当前行为，不改变 columns、filter、截断宽度、显示行数和排序。
- `AI 深度分析` 按钮行为改为展开方向列表，而不是立即发送固定 prompt。
- 方向列表在节点详情卡片内 inline 展示，最多 4 条，视觉样式复用现有 Agent follow-up suggestions 的按钮风格。
- 新增一个深模块：深度分析方向推荐器。
  - 输入：点击项、图表配置、列名、schema、语言。
  - 输出：最多 4 个方向，每个方向包含展示 label 和发送给 Agent 的 prompt。
  - 本地推荐器不访问 React 状态、不请求网络、不调用 LLM、不解析 SQL；AI 推荐方向通过独立轻量 API 按需调用。
- 方向推荐只使用 4 类信号：点击值、点击度量、图表类型、schema 字段类型。
- 主方向固定优先级：下钻 → 对比 → 时间趋势 → 明细查询。
- 主方向不满足条件时，按补位顺序补齐：占比 → 关联度量 → 异常/离群 → 环比/同比。
- 方向 prompt 使用自然语言 + 结构化上下文。
  - 必须包含锁定条件，例如 `city = '北京'`。
  - 必须包含分析动作，例如下钻、对比、趋势、明细、占比。
  - 必须包含相关分组字段和度量字段。
- 点击某个方向后发送对应 prompt，并收起当前节点详情或清空点击状态，避免重复展开旧选项。
- 中英文方向文案和 prompt 均由推荐器根据当前语言生成。

## Testing Decisions

- 当前项目没有测试框架配置，因此本 PRD 不要求新增 Jest/Vitest/Playwright 测试。
- 深度分析方向推荐器应被设计为可测试的纯函数；如果未来引入测试框架，应优先为该模块补单元测试。
- 好的测试应验证外部行为，而不是内部实现细节。
- 推荐器未来测试重点：
  - 给定分类维度、数值度量和额外维度字段时，优先返回下钻方向。
  - 给定多个同维节点时，返回对比方向。
  - schema 存在 Date/DateTime 字段时，返回时间趋势方向。
  - 任意有效输入都返回明细查询方向。
  - 条件不足时按占比、关联、异常、环比顺序补位。
  - 输出不超过 4 条。
  - 中文语言输出中文 label/prompt，英文语言输出英文 label/prompt。
- 手动验收应覆盖：
  - 单维度柱状图节点点击。
  - 多维度组合节点点击。
  - 多 series 图表节点点击。
  - 有 Date 字段和无 Date 字段的表。
  - 中文和英文界面。

## Out of Scope

- 不修改 Agent API 路由。
- 不让 LLM 默认阻塞本地方向展示。
- 不解析当前 SQL 的 GROUP BY、WHERE、CTE 或子查询。
- 不修改 ClickHouse 查询执行逻辑。
- 不修改节点详情下方明细表格。
- 不把 schema comment 用作展示名。
- 不新增用户自定义方向输入框。
- 不新增图表交互类型。
- 不改持久化聊天记录结构之外的历史迁移逻辑。

## Further Notes

- autoPivot 场景下，seriesName 可能代表透视后的维度值，而不是原始 yKey。实施时需要确保度量行文案不会误导用户。可采用 `seriesName = value` 的简洁展示，并在 prompt 中继续使用原始 yKey 作为度量字段。
- 如果点击事件返回的 row 缺少原始维度字段，应回退到现有 key 重建逻辑，避免表头为空。
- 如果 schema 缺失或为空，方向推荐器仍应至少返回明细查询方向。
- 该功能是 #7 Agent 自动可视化能力的体验增强，依赖图表点击、可视化配置和 Agent 聊天已存在。
